# 🎙 Алиса v2 — локальный ассистент

**«Яндекс Алиса, но только на твоём компьютере»** — локальный мозг, GUI-чат, голос и архитектура для бесплатных веб-сервисов. Никаких подписок и облаков: **0 ₽**.

Обычные вопросы отвечает `Ollama + qwen3.5:9b`; интерфейс никогда не замирает, а каждое долгое действие показывает статус в ленте.

## Возможности

- 🪟 **GUI-окно чата** — `python alice.py` по умолчанию, тёмная тема, стриминг ответа, авто-прокрутка
- ⚡ **Надёжный холодный старт** — HTTP-проверка API, `ollama app.exe` первым, диагностика процессов, лог и `/старт`
- 🧠 **Локальный мозг** — модель ~6 ГБ помещается в 8 ГБ видеопамяти
- 💬 **Текстовый чат в консоли** — `python alice.py --text`
- 🎤 **Голосовой режим** — `python alice.py --voice`
- 🇷🇺 **Русский язык** — промпт, интерфейс и голоса заточены под русский
- 💾 **Контекст 8192 токена** — диалог не теряется через пару реплик

## Требования

- Windows 10/11
- Python 3.9+ (проверено на 3.13)
- [Ollama](https://ollama.com) 0.32
- `PySide6` и `Playwright` (уже установлены; ставятся из `requirements.txt`)
- `psutil`, `requests`/`httpx`, `pywin32` уже стоят на ПК владельца; **новых зависимостей нет**
- GPU от 8 ГБ (проверено: RTX 3070 8 ГБ; на CPU тоже работает, но медленнее)
- Микрофон и колонки/наушники — для голосовых сценариев

**Проверено на:** RTX 3070 8 ГБ · Intel i5-12400 · 16 ГБ DDR4 · Windows

## Установка

### 1. Мозг (Ollama + модель)

```powershell
winget install Ollama.Ollama
ollama pull qwen3.5:9b
```

Алиса при старте сначала делает прямой `GET http://127.0.0.1:11434/api/version` (таймаут 2 с). Если API отвечает — лишние процессы не запускаются. Если нет, она смотрит `ollama*` через `psutil`, ждёт 10 с при «трей жив, сервер мёртв» (баг [ollama/ollama#12691](https://github.com/ollama/ollama/issues/12691)), затем перезапускает **пару** процессов: сначала `ollama app.exe`, потом `ollama.exe serve` — иначе трей сразу поднимет сервер заново ([ollama/ollama#14761](https://github.com/ollama/ollama/issues/14761)). Каталог установки перечисляется динамически: ищутся `ollama app.exe`, `ollama.exe`, `OllamaServer.exe`. Порядок запуска: `ollama app.exe` → `ollama.exe serve` → `OllamaServer.exe` → `ollama.exe list`. Дочерним процессам принудительно передаются `OLLAMA_CONTEXT_LENGTH=8192` и `OLLAMA_FLASH_ATTENTION=1`; `stdout`/`stderr` идут в лог, а не в `DEVNULL`.

#### Автозагрузка Ollama при входе в Windows

Правильный ярлык в `shell:startup` — **строго на `ollama app.exe`**. Ярлык на CLI `ollama.exe` только моргает и закрывается: это типичная причина «стоит в автозагрузке, но не работает».

Самый простой путь — из Алисы:

```text
/автозагрузка
```

Команда сама найдёт `%LOCALAPPDATA%\Programs\Ollama\ollama app.exe`, создаст/проверит `Ollama.lnk` через `pywin32` COM (или `powershell.exe`) и напишет «Ярлык создан: …» / «Ярлык уже есть: …» / «Ollama не установлена: …».

Готовая команда-однострочник для PowerShell (`Win+R` → `powershell` → Enter), официальный рецепт `WScript.Shell.CreateShortcut`:

```powershell
powershell -NoProfile -Command '$s=(New-Object -ComObject WScript.Shell).CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\Ollama.lnk"); $s.TargetPath="$env:LOCALAPPDATA\Programs\Ollama\ollama app.exe"; $s.WorkingDirectory="$env:LOCALAPPDATA\Programs\Ollama"; $s.Save()'
```

То же вручную: `Win+R` → `shell:startup` → Enter → создай ярлык на `%LOCALAPPDATA%\Programs\Ollama\ollama app.exe`.

**Проверка после перезагрузки:**

1. В трее есть значок Ollama.
2. `curl http://127.0.0.1:11434/api/version` отвечает JSON с версией.
3. `python alice.py` сразу показывает 🟢 Ollama и не запускает ни одного лишнего процесса.

Запасная модель для слабого железа: `ollama pull qwen2.5-coder:7b`.

### Холодный старт и диагностика

1. Прямой HTTP `GET /api/version` с таймаутом **2 с**. Ответил — сразу 🟢, без лишних запусков.
2. Не ответил — Алиса показывает найденные `ollama*` процессы с PID. Если трей/сервер есть, но API мёртв, ждёт **10 с** (статус раз в секунду), затем пишет «Ollama запущена, но сервер не отвечает (известный баг) — перезапускаю» и убивает оба процесса.
3. Запускает `ollama app.exe` первым; при неудаче — `ollama.exe serve`, `OllamaServer.exe`, затем официальный клиентский `ollama.exe list`. Статус «Жду Ollama… (N c)» обновляется раз в секунду, список процессов — каждые 5 с, HTTP опрашивается каждые **0.5 с до 30 с**.
4. Если порт **11434 занят**, а API молчит — красная строка «Порт 11434 занят, но Ollama не отвечает — перезапусти Ollama (или нажми Повторить)», ввод разблокирован, окно живое.
5. Любая другая неудача — красная строка с перечислением путей, exit codes и `stderr`, ссылка на лог, команда `/старт` или кнопка **Повторить** запускают `ensure` заново в фоне. Вечных зависаний нет.
6. После подъёма API проверяется `/api/tags`: модель есть → 🟢; нет → 🟡 «Модель не скачана: выполните ollama pull qwen3.5:9b» (сама 6 ГБ не качает).

**Лог:** `%LOCALAPPDATA%\Alice\alice.log` (на Linux/macOS `~/.alice/alice.log`). При открытии обрезается до ~1 МБ; пишет время, все шаги, найденные exe, PID, exit codes и `stderr`. Каждая красная ошибка в ленте ссылается на этот путь.

**Один экземпляр:** мьютекс Windows (`flock` на Linux/macOS) не даёт второму `python alice.py` сломать первый — второй печатает «Алиса уже запущена» и завершается.

Все долгие действия выполняются в `QThread`; таймаут ответа локальной модели — **120 сек**. `ensure` единый для GUI, `--text` и `--voice`.

## Настройка

Переменные в начале `alice.py`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MODEL` | `qwen3.5:9b` | какая модель отвечает |
| `NUM_CTX` | `8192` | размер контекста диалога |
| `LLM_TIMEOUT` | `120` | таймаут ответа локальной модели |
| `WHISPER_MODEL` | `small` | точность распознавания: `small` / `medium` |
| `VOICE_NAME` | `ru_RU-irina-medium` | голос (мужской: `ru_RU-ruslan-medium`) |
| `SILENCE_S` | `1.2` | пауза в секундах = конец фразы |
| `SYSTEM` | — | характер и стиль ответов |

## Как устроено

```
Окно PySide6 / консоль / микрофон
  → HTTP /api/version + psutil + лог alice.log
  → app.exe → serve → OllamaServer.exe → ollama.exe list (до 30 с)
  → /api/tags → локальная модель (8k контекста, стриминг, 120 с)
  → Piper / динамики (для голоса)
```

## Браузер ассистента (настраивается один раз)

Playwright работает в отдельном профиле, чтобы не трогать личные вкладки:

- Windows: `%LOCALAPPDATA%\Alice\browser-profile`
- Linux/macOS: `~/.alice/browser-profile`

Запусти `/браузер` (или кнопку **Браузер**) — откроется вкладка DeepSeek. Один раз залогинься и закрой окно браузера. Профиль запоминает куки, поэтому больше логин не просит. Ожидание настройки — до **5 минут**.

| Команда | Что делает |
|---|---|
| `д: <вопрос>` | отправить вопрос в DeepSeek |
| кнопка **DeepSeek** | то же самое для текста в поле ввода |
| `/браузер` | открыть профиль для одноразового логина |

## Умный вопрос через DeepSeek

1. «Открываю DeepSeek…» — открывается `chat.deepseek.com` в профиле ассистента.
2. Если не залогинен — «Залогинься в окне браузера (один раз)», ожидание до **5 минут**.
3. Запрос вставляется в поле и отправляется; ответ ждём до **60 сек** с индикатором «Жду ответ DeepSeek… (N c)».
4. Капча/подтверждение — «Ответь на капчу в браузере», ожидание до **3 минут**, затем продолжение.
5. Ответ появляется в ленте как `DeepSeek: …` и уходит в историю диалога.

Ошибки сети, изменённой разметки или ненайденного поля выводятся красной строкой «Система: …», состояние браузера сбрасывается, ввод разблокируется. Все CSS/селекторы DeepSeek изолированы в одном блоке `WEB_SELECTORS` в `alice.py` — при обновлении сайта правится только он.


## Музыка VK Музыка

С этого этапа `/браузер` открывает также вкладку VK Музыки: один раз залогинься и там, профиль сохранит куки. Текстовые и голосовые команды идут через тот же профиль браузера:

| Команда | Ответ в ленте |
|---|---|
| `включи <исполнитель> [трек]` | «Ищу в VK Музыке: …» → «Включаю: Исполнитель — Трек» |
| `пауза` | «Пауза.» |
| `продолжи` | «Продолжаю.» |
| `дальше` | «Следующий трек.» |
| `выключи музыку` | «Музыка выключена.» |

Если точного совпадения нет — «Не нашёл. Ближайшие варианты: …» (топ-3). Если не залогинен — «Открой VK в окне браузера ассистента, залогинься» и ожидание до **5 минут**. Селекторы VK изолированы в `WEB_SELECTORS`; при смене разметки Алиса возвращает понятную русскую ошибку, а не падает.

Яндекс Музыка оставлена архитектурной заготовкой (`MUSIC_PROVIDERS["yandex"] = False`) и подключается позже по той же схеме.


## Индикаторы здоровья

В шапке GUI три индикатора — **Ollama / Модель / Браузер**:

- 🟢 зелёный — всё ок
- 🟡 жёлтый — проверяется / профиль ещё не настроен
- 🔴 красный — ошибка или зависимость отсутствует

Они обновляются в фоне раз в **5 секунд** через отдельный `QThread`. Команда `/статус` печатает то же самое текстом: версию `2.0`, активную модель, состояние Ollama/браузера и размер истории.


## Голос в GUI

Кнопка **🎙** записывает фразу, распознаёт её `faster-whisper` и кладёт текст **в поле ввода, не отправляя сам**. Дальше можно отредактировать и нажать Enter. Статусы «Грузим распознавание речи…», «Слушаю… (N c)» идут в ленте. Нет микрофона или слишком шумно — понятная ошибка, окно не падает.

`--voice` работает как раньше, но теперь голосовые `д:` и музыкальные команды проходят через **тот же** `classify_command()` и те же обработчики браузера, что GUI и `--text` — логика не дублируется.

| Что | Лимит |
|---|---|
| `GET /api/version` | 2 сек |
| Ожидание при «трей жив, API мёртв» | 10 сек |
| Опрос готовности Ollama | каждые 0.5 сек, всего до 30 сек |
| Каждый способ запуска | 5 сек (`ollama.exe list` — 10 сек) |
| Одноразовая настройка профиля браузера | 5 минут |
| Ответ локальной модели | 120 сек |
| Логин в DeepSeek / VK | 5 минут |
| Ответ DeepSeek | 60 сек |
| Капча / подтверждение | 3 минуты |
| Обновление индикаторов | каждые 5 сек |
| COM/PowerShell создание ярлыка | 15 сек |
